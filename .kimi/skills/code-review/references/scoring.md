# 评分细则

## 评分维度与权重

| 维度 | 权重 | 核心考察点 |
|------|------|-----------|
| 单一职责 (SRP) | 20% | 类/函数是否只做一件事；文件是否是多模块拼接 |
| 开闭原则 (OCP) | 15% | 扩展是否需要修改核心类；是否有 hardcoded 枚举/序列 |
| 里氏替换 (LSP) | 10% | 子类/实现是否可以替换基类而不破坏行为 |
| 接口隔离 (ISP) | 10% | 是否存在"胖接口"；子类是否被迫实现无关方法 |
| 依赖倒置 (DIP) | 15% | 高层是否直接依赖具体实现；是否有统一配置/注入机制 |
| 契约精神 | 15% | 函数签名是否诚实；类型/文档覆盖率；错误契约是否统一 |
| 代码异味 | 15% | 危险调用、重复代码、超长函数、注释死代码、拼写错误 |

> 微服务项目额外评估 Clean Architecture 分层（计入 DIP 和 OCP 维度）。

---

## 各维度扣分参考

### SRP
- 单个函数 > 100 行：-15
- 单个函数 > 50 行（每个）：-3（上限 -20）
- 一个文件承担 3+ 种职责：-10
- `__init__` / `main.rs` 承担配置+装配+基础设施：-15

### OCP
- pipeline 序列 hardcoded 在类/函数内部：-20
- 新增功能必须修改核心类：-15
- 并行维护两套相同逻辑（版本已分叉）：-20
- Clean Architecture 违反：基础设施层反向依赖领域层（如 Domain 导入 DB 驱动）：-20
- 无明确分层（所有代码平铺在一级目录）：-10

### LSP
- 构造函数接收参数但静默覆盖：-20
- 子类重写破坏基类 invariant：-15
- Rust: trait 实现 panic!（未在 trait 文档中声明）：-15

### ISP
- 横切逻辑在每个子类重复实现：-15
- Rust: trait 包含大量 default method 但子类只用其中少数：-10
- Node/TS: 一个 interface 包含多个不相关职责的方法：-10

### DIP
- Python: `os.getenv` 散布 > 50 处：-20；20-50 处：-10
- Node/TS: `process.env.XXX` 散布 > 10 处（未集中到 config 模块）：-15
- Rust: 直接 `new ConcreteType` 而非 `dyn Trait` 注入：-10
- 全局单例作为隐式依赖（无注入）：-15
- 微服务: 硬编码服务地址（未走环境变量/服务发现）：-15

### 契约精神
- 函数签名与行为不一致（接收参数却忽略）：-25
- Python 类型注解覆盖率 < 50%：-15；50-80%：-8
- TypeScript `any` 类型 > 10 处：-20；1-10 处：-8
- TypeScript `@ts-ignore` / `@ts-nocheck`：每处 -5
- 公开函数 docstring/doc-comment/JSDoc 覆盖率 < 50%：-15
- Rust: `pub fn` 无 `///` 注释覆盖率 < 50%：-10
- 错误处理契约不统一（混用异常/返回码/空值/Result）：-10
- Rust: library crate 中 `panic!`（未在文档中声明 panics）：-15
- Node: `.then()` 无对应 `.catch()` 或无 `try/catch`：每个文件 -3

### 代码异味
- Python 生产代码 `exit()` 调用：每处 -15
- Rust 生产路径 `unwrap()` / `expect()`（非 test）：每处 -5，超 10 处 -20
- Rust `unsafe` 块无注释说明：每处 -10
- TypeScript `eval()` / `execSync()`：每处 -10
- 拼写错误导致静默 bug：每处 -10
- `sys.path.append` hack > 10 处：-10
- 超长函数 > 50 行数量 > 20 个：-10
- 重复文件对 > 5 对：-10
- 注释代码 > 50 行：-5
- 硬编码密钥/端口/地址（任意语言）：每处 -5，超 5 处 -20

## 微服务专项扣分（叠加到 DIP / OCP 维度）

| 问题 | 扣分 |
|------|------|
| 跨服务循环依赖（A→B→A） | -30 |
| 服务间直接共享 model 代码（非 proto 生成） | -20 |
| 无统一 proto/OpenAPI 定义，靠手写 HTTP 客户端 | -15 |
| 硬编码服务地址（http://user-service:8080） | 每处 -10 |
| 各服务错误响应结构不统一 | -10 |
| 无 traceId/requestId 跨服务追踪 | -10 |
| 配置散落在各服务代码（未走环境变量/ConfigMap） | -10 |

---

## 起始分

各维度均从 100 分开始扣，最低 0 分，加权后得综合分。
